Validate format compliance against RFC specifications, probe live DNS Mail Exchange (MX) and fallback A/AAAA records, and identify delivery risks before launching campaigns.

Likely to be delivered

Syntax passes RFC rules and verified mail-routing MX servers accept traffic. Note: Recipient delivery is subject to mailbox quota and spam filtering.

Likely to bounce

Invalid syntax, nonexistent domain (NXDOMAIN), RFC 7505 Null MX record, or confirmed absence of mail routes. Mail will be permanently rejected.

Unknown

Domain MX routing is active, but individual mailbox existence could not be confirmed without outbound SMTP (port 25 blocked) or an HTTPS provider.

Non-Invasive Verification Pipeline

EmailCheck uses secure HTTPS connections to supported verification providers and does not depend on blocked outbound SMTP port 25 connections. The pipeline checks:

  1. Email syntax
  2. Email normalization
  3. Disposable-domain detection
  4. DNS domain validation
  5. MX and Null MX validation
  6. Recipient verification through a configured provider

No verification emails are sent by this diagnostic process.

Classification Categories

Likely to be delivered

Email has valid RFC syntax, resolves to an active domain with usable MX records, is not a disposable provider, and recipient inbox was confirmed deliverable by verification provider or SMTP 250 acceptance.

High deliverability confidence. Inbox delivery subject to recipient mailbox quotas and spam filters.
Likely to bounce

Malformed syntax, domain confirmed nonexistent (NXDOMAIN), domain publishes an RFC 7505 Null MX record, has no mail routing, or recipient was confirmed undeliverable.

Emails sent to this address will almost certainly bounce or be rejected.
Unknown

Domain mail routing is active, but individual mailbox existence could not be confirmed without outbound SMTP (port 25 blocked) or an HTTPS provider. Also assigned to catch-all servers, disposable domains, and DNS timeouts.

Transparent fallback: never guesses deliverability when diagnostics are inconclusive.

🔒 Port 25 Replacement & Privacy Architecture

EmailCheck completely replaces direct SMTP port 25 probing with secure, cloud-friendly HTTPS APIs (port 443). We never send emails, never issue SMTP DATA commands, and do not store submitted email lists in permanent databases. All processing occurs in memory and user data is never retained.
