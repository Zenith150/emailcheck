How Email Verification Works

1. Likely to be Delivered

The email has valid RFC 5322 syntax, points to a real domain with active MX mail exchangers, and passed non-invasive deliverability diagnostics.

Estimated deliverability. Inbox placement still depends on spam filters and recipient policy.
2. Likely to Bounce

The address has malformed syntax, the domain does not exist in DNS (NXDOMAIN), lacks mail routing records, or an explicit rejection code was received.

Mail sent to these addresses will almost certainly fail or be rejected.
3. Unknown

Verification is inconclusive due to DNS timeouts, greylisting, catch-all domain configurations, or cloud platform restrictions on outbound port 25.

Safe assessment: Never assumes a mailbox exists if the server hides or generalizes status.

🔒 Privacy & Safety Guarantee

EmailCheck strictly adheres to non-invasive verification. We never send emails, never issue SMTP DATA commands, and do not store submitted email lists in permanent databases. All processing occurs in memory and user data is never retained.
